Purpose

What this tool is for

Linux desktops rarely use a single store. Apps arrive through apt, snaps, Flatpaks, Homebrew bottles, pipx tools, Rust crates, AppImages, and vendor .deb downloads — each with its own search, install, and upgrade story.

lpkg sits above those managers. You ask once; it searches enabled backends, picks the best source by your priority list, installs, tracks provenance in a local registry, and helps you upgrade, pin, export, or clean up without juggling five CLIs.

It does not replace apt or Flatpak — it orchestrates them so day-to-day package work feels consistent on Ubuntu and Debian-based systems.

Get started

Install lpkg

Pick one path. After install, confirm with lpkg --version.

One-liner

Downloads the latest GitHub release binary, or builds from source if a release asset is unavailable.

curl -fsSL https://raw.githubusercontent.com/MatoloJr/lpkg/main/scripts/install.sh | bash

Clone and make

Default prefix is /usr/local. Override with PREFIX, BINDIR, or DATADIR.

git clone https://github.com/MatoloJr/lpkg.git
cd lpkg
sudo make install

Debian package

make deb
sudo dpkg -i dist/lpkg_0.2.0_amd64.deb

Cargo

cargo install --git https://github.com/MatoloJr/lpkg.git

Configuration

How to customize lpkg

Behavior is driven by a user config file, optional alias maps, install layout, and JSON manifests — so you can tune backends without rebuilding.

Main config — ~/.config/lpkg/config.toml

Created on first run with sensible defaults. Edit it to change resolution order and which backends are active.

backend_priority = ["flatpak", "apt", "snap", "brew", "pipx", "cargo", "direct_deb", "appimage"]
apps_only = true
cache_ttl_hours = 24

[backends]
apt = true
snap = true
flatpak = true
brew = true
pipx = true
cargo = true
appimage = true
direct_deb = true

# Optional AppImage discovery roots
# appimage_paths = ["~/Applications", "~/.local/bin"]
  • backend_priority — order used when lpkg install has no --source. First match wins.
  • [backends] — set a backend to false to skip it in search/install/upgrade.
  • apps_only — prefer application-like packages when listing (backends that support the distinction).
  • appimage_paths — directories scanned for portable AppImages.
  • cache_ttl_hours — how long inventory scan cache is considered fresh.

Aliases — cross-backend identity

Packaged aliases live under /usr/local/share/lpkg/aliases.toml (or /usr/share/lpkg/). Drop a personal file at ~/.config/lpkg/aliases.toml to override and map one canonical name (e.g. firefox) to backend-specific IDs.

Install layout

When installing from source:

sudo make install PREFIX=/usr/local
# binary → $PREFIX/bin/lpkg
# data   → $PREFIX/share/lpkg/

Manifests — reproducible machine setup

Export your inventory, edit the JSON, then reinstall elsewhere with import or install --all.

lpkg export -o packages.json
lpkg import packages.json --dry-run
lpkg install --all
lpkg install --all my-packages.json

Install provenance is tracked in ~/.local/share/lpkg/registry.db (SQLite). That registry is separate from backend package databases and survives tool reinstalls until you delete it.

CLI

Commands

Search and install hit all enabled backends unless you pass --source. Use -a / --auto for replace-on-install and outdated-only upgrades.

CommandWhat it does
lpkg search <q…>Search every enabled backend for each query; merge and dedupe
lpkg install <id…>Install each id via best backend (or --source)
lpkg install --all [file]Install from a JSON manifest (default packages.json)
lpkg install … --autoRemove an existing install of the same id, then install
lpkg listInventory (--outdated, --duplicates, --format json)
lpkg upgradeUpgrade outdated packages only
lpkg upgrade --allRun each backend’s full upgrade
lpkg upgrade <id> --autoUpgrade only if outdated; no-op if current
lpkg uninstall <id>Remove a managed package (--purge, --source)
lpkg info / whichInspect candidates and which backend provides a package
lpkg cleanup / scan / doctorMaintenance and health checks
lpkg pin / export / importPinning and manifest round-trip

Examples

lpkg search firefox code
lpkg install firefox --auto
lpkg upgrade
lpkg upgrade --all
lpkg info firefox
lpkg which firefox

Removal

Uninstall packages vs uninstall lpkg

These are different operations. One removes software you manage with lpkg; the other removes the lpkg binary itself.

Managed packages

Remove an app or package

Use the CLI. This asks the underlying backend (apt, flatpak, …) to uninstall and updates lpkg’s registry. Optional --purge removes config where the backend supports it; --source picks which copy when duplicates exist. 

lpkg uninstall firefox
lpkg uninstall firefox --purge
lpkg uninstall code --source apt
The lpkg tool

Remove lpkg from your system

How you installed determines how you uninstall. make uninstall only deletes the binary and shared data under your install prefix — it does not remove user config or the registry.

Installed with clone + make

From the repo directory (use the same PREFIX you used for install; default is /usr/local): 

sudo make uninstall
# removes: $PREFIX/bin/lpkg
#          $PREFIX/share/lpkg/

Custom prefix example:

sudo make uninstall PREFIX=/usr/local

Installed from a .deb

sudo dpkg -r lpkg
# or
sudo apt remove lpkg

Installed with cargo

cargo uninstall lpkg

Installed via one-liner / manual binary

sudo rm -f /usr/local/bin/lpkg
sudo rm -rf /usr/local/share/lpkg

User data is kept on purpose. After removing the tool, you may still have ~/.config/lpkg/ (config, aliases) and ~/.local/share/lpkg/ (registry). To wipe those as well: 

rm -rf ~/.config/lpkg ~/.local/share/lpkg
